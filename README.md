# Where-Am-I

Telegram-бот для отметок путешественников в одной группе. Пользователь вводит `/set Минск, Беларусь` или `/set Минск Беларусь`; бот сохраняет введённый текст в Google Sheets. Проверяется только формат, географических запросов и словарей нет. Полные требования: [SPEC.md](SPEC.md).

## Команды

- `/set Город, Страна` — сохранить место и добавить событие в историю. Пробел вместо запятой тоже допускается.
- `/list` — текущие отметки с группировкой по тексту места, ссылками на участников и пагинацией.
- `/me` — последняя отметка и дата `ДД.ММ.ГГГГ` по времени Минска.
- `/help`, `/start` — краткая двухстрочная справка о `/set` и `/list`.

Все команды работают только в группе из `TELEGRAM_GROUP_ID`. При Privacy Mode используйте адресацию `/set@ИмяБота Минск Беларусь`, если короткая команда не доставляется. Имена пользователей, Telegram ID, текст места и HTML в ответах обрабатываются безопасно.

## Правила ввода

Длина — до 120 символов. При наличии запятой нужны ровно две непустые части с буквами: `Нью Йорк, США`. Без запятой нужны минимум два слова: `Нью Йорк США`. Ввод только города, пустая часть после запятой и координаты вида `53, 27` отклоняются. Существование города/страны, опечатки и порядок слов не проверяются.

Строка сохраняется целиком с сохранением регистра, написания и внутренних пробелов; убираются только пробелы по краям. Бот не пытается разделить составные названия на отдельные поля. В `/list` регистр, повторные пробелы и запятая игнорируются при группировке: `Минск, Беларусь` и `минск Беларусь` объединяются. Переводы, опечатки и обратный порядок слов считаются разными местами. Заголовок берётся из последней отметки группы.

## Google Sheets и новая схема

Используется одна Spreadsheet и два листа:

| Лист | Колонки в точном порядке |
| --- | --- |
| `Users` | `user_id`, `display_name`, `username`, `location`, `updated_at` |
| `LocationHistory` | `user_id`, `location`, `recorded_at` |

`location` — введённый текст целиком. `user_id` — строка; пустой username — пустая ячейка. Время хранится в ISO UTC. Все значения записываются через `stringValue`, поэтому пользовательский текст не выполняется как формула. Каждый успешный `/set`, включая повтор того же места, обновляет одну строку `Users` и добавляет одну строку истории одним атомарным `spreadsheets.batchUpdate`.

**Переход на новую стратегию:** на старте листы с другими заголовками очищаются и получают новую компактную схему. Старые записи и географические колонки не переносятся. Это согласованный сброс старых данных. После перехода совпадающие заголовки и все новые записи сохраняются при перезапусках. Остальные листы Spreadsheet не меняются. Не редактируйте заголовки и рабочие строки вручную.

В Google Cloud должен быть включён Google Sheets API. Spreadsheet предоставляется service account с ролью Editor. Файл создаётся владельцем вручную, рабочие листы создаёт приложение. JSON-ключ Google не коммитьте.

## Конфигурация

Скопируйте `.env.example` в `.env` для локального запуска или задайте переменные в Render Environment.

| Переменная | Назначение |
| --- | --- |
| `NODE_ENV` | `development` или `production`, по умолчанию `development` |
| `LOG_LEVEL` | `debug`, `info`, `warn`, `error`, `silent`; по умолчанию `info` |
| `PORT` | Порт HTTP; по умолчанию 3000, на Render предоставляется платформой |
| `PUBLIC_BASE_URL` | HTTPS origin сервиса, без пути `/telegram/webhook` |
| `TELEGRAM_BOT_TOKEN` | Секретный токен BotFather |
| `TELEGRAM_GROUP_ID` | Отрицательный числовой ID разрешённой группы |
| `TELEGRAM_WEBHOOK_SECRET` | 1–256 символов `A-Z a-z 0-9 _ -` |
| `GOOGLE_SPREADSHEET_ID` | ID Google Spreadsheet |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | Поле `client_email` из JSON-ключа |
| `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` | Полный PEM-ключ; поддерживаются настоящие переводы строк и буквальные `\n` |
| `RENDER_HEALTH_URL` | Только GitHub Actions: полный адрес `/health` |

Переменные геокодера больше не используются и не требуются. Старые переменные на Render можно удалить; их наличие не мешает запуску. Вручную в Render вводите значения без внешних кавычек. `.env`, логи и приватные ключи исключены из Git.

## Деплой на Render

1. Отправьте репозиторий в GitHub и создайте Render **Web Service**, runtime Node, один инстанс.
2. Build Command: `npm ci --include=dev && npm run build`.
3. Start Command: `node dist/scripts/register-webhook.js && npm run start`.
4. Environment: `NODE_VERSION=26`, `NODE_ENV=production`, остальные переменные из таблицы выше. Установите реальный адрес Render в `PUBLIC_BASE_URL`.
5. Health Check Path: `/health`. Дождитесь `webhook_setup_completed` и `app_ready`.
6. Проверьте `https://<render-host>/health`: ожидается `200 {"status":"ok"}`. Затем проверьте команды в группе.

Setup регистрирует webhook с секретом, `max_connections=1` и `allowed_updates=["message","callback_query","my_chat_member"]`. Он также обновляет описание бота и меню команд. Ошибка webhook останавливает запуск; ошибка меню группы логируется как предупреждение. Бота можно добавить после деплоя: событие `my_chat_member` повторит настройку меню без перезапуска. Команды работают независимо от меню. Регистрация не удаляет ожидающие обновления.

## Keep-alive

В GitHub Settings → Secrets and variables → Actions → **Variables** задайте `RENDER_HEALTH_URL=https://<render-host>/health`. Workflow `Render keep-alive` выполняется каждые 10 минут и вручную через Run workflow. Он должен находиться в default branch.

Render Free может засыпать после простоя, расписание GitHub может задерживаться. Проверяйте текущие [ограничения Render](https://render.com/docs/free) и [расписаний GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). Постоянная доступность не гарантируется. Пользовательские данные хранятся в Google Sheets, а не на диске Render.

## Локальный запуск и проверки

Нужен Node.js 26.x:

```sh
npm ci
npm run test
npm run lint
npm run typecheck
npm run build
npm run dev
```

Для локального webhook нужен HTTPS-туннель к порту 3000, его адрес в `PUBLIC_BASE_URL` и `npm run webhook:set`. Этот шаг переключает Telegram с Render на локальный адрес. Одновременно используйте одну установку бота. `npm run start` запускает скомпилированную версию. Polling не используется.

CI запускает test, lint, typecheck и build на Node.js 26. Секреты и настоящие API в тестах не нужны. Override `minimatch` фиксирует уязвимость зависимости ESLint; при обновлении инструментов проверяйте `npm audit` и lint.

## Логи и диагностика

JSON-логи идут в stdout и доступны в Render → Logs. `info` фиксирует запуск, сохранение отметок и команды; `warn` — отклонённый ввод, отсутствие группы, ошибки меню и сброс старой схемы; `error` — сбои Google Sheets, Telegram и запуска; `debug` — подробности операций и webhook. `/health` не засоряет логи.

Для ошибок выводятся безопасный код, тип, HTTP-статус и длительность. Для команд — диагностический `update_id`, без хранения и дедупликации. Токены, ключи, текст места, имена, username и Telegram user ID не логируются. `location_saved` означает подтверждённую запись, даже если затем не удалось отправить ответ Telegram.

Если бот молчит, проверьте ID группы, адресацию команды и webhook. Если не видны подсказки команд, введите `/` и переоткройте чат. При временной ошибке найдите `sheets_*_failed` или `command_failed` в логах. При неопределённом результате записи автоматического повтора нет: сначала проверьте таблицу.

В MVP нет удаления/TTL, карт, просмотра истории в Telegram, нескольких групп и дедупликации updates. Выход участника не меняет данные. Повторная доставка webhook может добавить лишнюю историческую строку. История доступна владельцу Spreadsheet.
