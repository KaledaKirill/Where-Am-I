# Where-Am-I

Telegram-бот для путешественников одной группы. Отправьте геолокацию **боту в личку**, и он сохранит отметку, добавит событие истории и обновит общий список в закрепе группы. Место определяется через Geoapify; координаты остаются в Google Sheets и не показываются в списке. Полные требования и архитектура: [SPEC.md](SPEC.md).

## Использование

В личке:

- `/start` — приветствие, инструкция и кнопка `📍 Отправить геолокацию`.
- `/help` — краткая инструкция.
- `/list` — полный текущий список, сгруппированный по местам.

В целевой группе доступна только `/list`. Геопозиции в группе не создают отметок. Бот проверяет членство перед личной отметкой или выдачей списка. Редактирования Live Location игнорируются. Каждая новая отправка, даже из того же места, добавляет историю. Выход из группы не меняет данные.

`/list` и закреп имеют одинаковый формат: место, Telegram-имена и ссылки на профили, включая пользователей без username. Пагинации и сокращения списка нет. Если текст превысит лимит Telegram, ошибка будет залогирована.

## Google Sheets

Одна Spreadsheet, три рабочих листа:

| Лист | Колонки |
| --- | --- |
| `Users` | `user_id`, `display_name`, `username`, `location`, `updated_at`, `city`, `region`, `country`, `latitude`, `longitude`, `coordinate_source` |
| `LocationHistory` | `user_id`, `location`, `recorded_at`, `city`, `region`, `country`, `latitude`, `longitude`, `coordinate_source` |
| `Settings` | `key`, `value` |

Одна строка Users на user ID. `location` — название для показа, `city` может быть пустым. Источник `telegram` означает исходные координаты геопозиции; `geocoded` — приближённые координаты старой текстовой отметки. Новые даты — ISO UTC. Пользовательские значения записываются как строки, без исполнения формул. Users и история сохраняются одним атомарным batchUpdate.

Settings хранит только `pinned_message_id`. Бот создаёт сообщение, сохраняет ID, закрепляет и затем редактирует его при старте и после успешных отметок. Удалённое сообщение восстанавливается. Сбой закрепа не откатывает отметку; следующая попытка использует данные из Sheets.

Отсутствующие листы создаются автоматически. **Старые несовместимые заголовки никогда не очищаются при запуске:** новая версия обслуживает HTTP в ожидании ручной миграции. Доступ к данным включается после миграции при следующем обращении, без перезапуска. Порядок колонок может отличаться, дополнительные поля сохраняются. Places не используется; посторонние листы не удаляются. Не редактируйте рабочие строки одновременно с ботом.

В Google Cloud включите Sheets API и предоставьте Spreadsheet service account с ролью Editor. Сам файл создаёт владелец. Бот должен быть администратором Telegram-группы с правом закреплять и отправлять сообщения. Администраторские права нужны также для надёжной [проверки членства](https://core.telegram.org/bots/api#getchatmember). Privacy Mode можно оставить включённым.

## Конфигурация

Скопируйте `.env.example` в `.env` или задайте переменные в Render Environment.

| Переменная | Назначение |
| --- | --- |
| `NODE_ENV` | `development` по умолчанию; `production` на Render |
| `LOG_LEVEL` | `debug`, `info`, `warn`, `error`, `silent`; по умолчанию `info` |
| `PORT` | HTTP-порт, по умолчанию 3000; на Render предоставляет платформа |
| `PUBLIC_BASE_URL` | HTTPS origin сервиса, без пути webhook |
| `TELEGRAM_BOT_TOKEN` | Токен BotFather |
| `TELEGRAM_GROUP_ID` | Отрицательный числовой ID целевой группы |
| `TELEGRAM_WEBHOOK_SECRET` | 1–256 символов `A-Z a-z 0-9 _ -` |
| `GOOGLE_SPREADSHEET_ID` | ID Spreadsheet |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | `client_email` service account |
| `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` | Полный PEM, поддерживаются переводы строк и буквальные `\n` |
| `GEOAPIFY_API_KEY` | Ключ Geoapify для reverse geocoding и одноразовой миграции |
| `RENDER_HEALTH_URL` | Только repository Variables GitHub Actions: полный HTTPS URL `/health` |

Вводите значения на Render без внешних кавычек. Старые Nominatim-переменные не используются. `.env`, ключи, логи и миграционные артефакты исключены из Git.

## Одноразовая миграция перед деплоем

Миграция выполняется вручную отдельным скриптом. Она не подключена к CI/CD, сборке, старту или автоматическому деплою. После перехода скрипт можно удалить.

Сначала задайте Geoapify-ключ и выполните:

```sh
npm run migrate:locations -- --dry-run
```

Без аргументов тоже используется dry-run. Скрипт читает реальные заголовки и сохраняет **все исходные строки** в `migration-artifacts/<timestamp>/backup.json`, затем создаёт `preview.json` и `report.json`. Google Sheets в этом режиме не меняются. Отчёт содержит числа исходных, перенесённых и пропущенных строк, неизвестные/неоднозначные места и причины пропусков. Неизвестная схема требует явного сопоставления колонок.

Правила учитывают комментарии `Тверь(впишу) Россия`, стрелочные маршруты, регистр, сокращения вроде `спб` и регион Бали. Для маршрута берётся конечное место без создания дополнительных событий. Несколько уверенных разных кандидатов требуют ручной проверки. Геокодирование последовательное с паузами, без повторов; при 429 или сбое провайдера применение блокируется.

При необходимости создайте локальный JSON с переопределениями исходных строк:

```json
{
  "неоднозначное место": "Уточнённое место, Страна",
  "исключить эту запись": null
}
```

```sh
npm run migrate:locations -- --dry-run --overrides=overrides.json
```

Скрипт сохраняет исходные даты, user ID, существующие события и дополнительные поля; исходный текст остаётся также в `legacy_location`. Недостающие даты и события не выдумываются. Пропущенные записи остаются в backup и отчёте. Повторный запуск не дописывает историю. Backup содержит значения и формулы, но не оформление таблицы; для полного восстановления можно дополнительно скопировать Spreadsheet в Google Drive.

Если у существующего события истории нет даты, оно переносится с пустой датой и предупреждением в отчёте. Для PowerShell используйте `npm.cmd --% run migrate:locations -- --dry-run --overrides=overrides.json`, если оболочка не передаёт аргументы через `npm.ps1`.

После проверки preview/отчёта и **отдельного разрешения владельца** убедитесь, что Render уже переключился на новую версию и завершил старый процесс, затем запустите:

```sh
npm run migrate:locations -- --apply --overrides=overrides.json
```

Если overrides не нужны, уберите этот аргумент. Apply создаёт свежую резервную копию, повторно сверяет источник и одной атомарной операцией обновляет рабочие листы. Settings и посторонние листы сохраняются. Отчёты содержат персональные данные: храните их надёжно, overrides с такими данными также не коммитьте.

## Безопасный порядок деплоя на Render

1. Подготовьте `GEOAPIFY_API_KEY` локально и в Render, дайте боту права администратора и закрепления.
2. Выполните dry-run, проверьте пропуски и overrides. Сохраните резервную копию вне временного диска Render.
3. Сначала разверните новую версию. На старой схеме она работает в ожидании ручной миграции и возвращает временную ошибку при обращении к данным. Старые записи сохраняются.
4. Разверните новую версию одним инстансом. Build Command: `npm ci --include=dev && npm run build`.
5. Start Command: `node dist/scripts/register-webhook.js && npm run start`. Environment: `NODE_VERSION=26`, `NODE_ENV=production`, остальные значения из таблицы. В `PUBLIC_BASE_URL` — реальный HTTPS origin Render.
6. Health Check Path: `/health`. Дождитесь `webhook_setup_completed` и `app_ready`. Проверьте `200 {"status":"ok"}`, `X-App-Version: 3.0` и `X-App-Revision` с SHA нового коммита. Дождитесь завершения старого процесса Render, затем выполните разрешённый apply. Старую версию после миграции запускать нельзя: она умеет очищать несовместимую схему.
7. Проверьте личные `/start`, геопозицию, запись истории, `/list` и закреп в группе. Затем можно восстановить обычный автодеплой и удалить одноразовый скрипт с его тестами и npm-командой.

Setup регистрирует защищённый webhook с `max_connections=1`, `allowed_updates=["message","callback_query","my_chat_member"]`, без удаления ожидающих updates. Он обновляет описание и меню для лички/группы. Ошибка webhook останавливает запуск; ошибка меню целевой группы логируется как предупреждение. При добавлении бота позже меню этой группы устанавливается снова. Polling не используется.

## Локальный запуск и проверки

Нужен Node.js 26.x:

```sh
npm ci
npm run test
npm run lint
npm run typecheck
npm run build
npm run dev
```

Для локального webhook нужен HTTPS-туннель к порту 3000, его origin в `PUBLIC_BASE_URL` и `npm run webhook:set`. Это переключает Telegram с Render на локальный адрес. Используйте одну установку бота одновременно. `npm run start` запускает собранную версию.

CI запускает test, lint, typecheck и build на Node.js 26 без секретов и настоящих API. Миграционные тесты используют моки и не запускают миграцию production. Override `minimatch` фиксирует уязвимость зависимости ESLint; при обновлении инструментов проверяйте `npm audit` и lint.

## Keep-alive и диагностика

В GitHub Settings → Secrets and variables → Actions → Variables задайте `RENDER_HEALTH_URL=https://<render-host>/health`. Workflow `Render keep-alive` выполняется каждые 10 минут и вручную через Run workflow; он должен находиться в default branch. Render Free может засыпать, расписание GitHub может задерживаться: [ограничения Render](https://render.com/docs/free), [расписания Actions](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule). Данные хранятся в Sheets, а не на диске Render.

JSON-логи идут в stdout/Render Logs. `info` — запуск и сохранение, `warn` — недоступное меню или чужой чат, `error` — ошибки Sheets, геокодера, Telegram и закрепа. Ошибки содержат безопасный код/HTTP-статус и длительность; SDK payload, stack, токены, координаты и персональные данные не выводятся. `/health` не засоряет логи. `location_saved` означает подтверждённую запись, даже если ответ Telegram затем не доставлен.

При `sheets_migration_required` новая версия ожидает ручную миграцию; следующее обращение после неё подхватит новую схему. При сбое закрепа проверьте администраторские права; данные уже сохранены, повторная геопозиция добавит ещё одно событие истории. При неопределённом результате записи сначала проверьте таблицу: автоматического повтора нет. Повторная доставка webhook может добавить лишнюю историческую строку. Нет удаления/TTL, карт, просмотра истории в Telegram и поддержки нескольких групп.
