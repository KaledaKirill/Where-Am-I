# Where-Am-I

Telegram-бот для путешественников одной группы. Отправьте геолокацию или текст `Город Страна` **боту в личку**, и он сохранит отметку, добавит событие истории и обновит общий список в закрепе группы. После отметки можно указать пункт назначения. `/find` помогает найти тех, кто уже находится в нужном месте или планирует приехать. Места определяются через Geoapify; координаты остаются в Google Sheets. Полные требования и архитектура: [SPEC.md](SPEC.md).

## Использование

В личке:

- `/start` — приветствие, инструкция и кнопки действий; отменяет незавершённый ввод.
- `/help` — инструкция без прерывания текущего ввода.
- `/list` — полный текущий список, сгруппированный по местам.
- `/find` или `🔎 Найти путешественников` — поиск по стране, региону, району или населённому пункту: `Россия`, `Тверская область`, `Москва`, `Москва Россия`.
- `/destination` или `✈️ Изменить планы` — изменить пункт назначения без новой отметки.
- `/cancel` — отменить незавершённый ввод, сохранив уже записанные данные.

Отметиться можно кнопкой `📍 Отправить геолокацию`, через скрепку → геопозиция или текстом: `Москва Россия`, `Нижний Новгород Россия`, `Берлин Германия`. Кнопка `📍 Указать место текстом` переключает ввод на текущую отметку из другого диалога. Составные названия населённых пунктов и стран поддерживаются без разделения по последнему слову.

После каждой успешной отметки бот спрашивает `✈️ Куда направляешься?`. Укажите населённый пункт и страну или нажмите `Пока никуда не планирую`, чтобы очистить прежние планы. До явного изменения прежний пункт назначения сохраняется. Планы не добавляют историю и не обновляют закреп.

Единственный точный уверенный результат принимается сразу. Исправленные и неоднозначные названия требуют выбора inline-кнопкой; низкая уверенность и неверный формат требуют уточнения. Без проверки произвольный текст не записывается. Назначение доступно после первой текущей отметки. При поиске показываются категории `📍 Сейчас находятся здесь` и `✈️ Планируют сюда приехать`, один человек может входить в обе.

`/find` заменяет незавершённый диалог; новая Telegram-геолокация всегда является текущей отметкой и снова открывает вопрос о планах. `/help` и `/list` сохраняют режим ввода. Новое название или переключение режима делает предыдущие inline-кнопки неактуальными. Состояние диалога хранится только в памяти процесса: после перезапуска используйте `/destination`, `/find` или начните отметку заново. Сохранённые данные остаются в Sheets.

В целевой группе доступна только `/list`. Геопозиции в группе не создают отметок. Бот проверяет членство перед личной отметкой, поиском, выдачей списка, изменением планов и применением inline-выбора. Редактирования Live Location игнорируются. Каждая новая отправка, даже из того же места, добавляет историю. Выход из группы не меняет данные.

`/list` и закреп показывают **только текущие местоположения**: место, Telegram-имена и ссылки на профили, включая пользователей без username. Планы и координаты не публикуются. При превышении 4096 символов после разбора HTML полный список делится на несколько сообщений; в группе закрепляются все части. Пагинации и сокращения списка нет.

## Google Sheets

Одна Spreadsheet, три рабочих листа:

| Лист | Колонки |
| --- | --- |
| `Users` | `user_id`, `display_name`, `username`, `location`, `updated_at`, `city`, `region`, `country`, `latitude`, `longitude`, `coordinate_source`, `country_code`, `county`, `destination_city`, `destination_region`, `destination_county`, `destination_country`, `destination_country_code`, `destination_latitude`, `destination_longitude` |
| `LocationHistory` | `user_id`, `location`, `recorded_at`, `city`, `region`, `country`, `latitude`, `longitude`, `coordinate_source`, `country_code`, `county` |
| `Settings` | `key`, `value` |

Одна строка Users на user ID. `location` — название для показа, `city` может быть пустым у геопозиций вне населённых пунктов. `region` — область/state, при её отсутствии county; `county` отдельно хранит район. `country_code` — ISO alpha-2 в нижнем регистре. Источник `telegram` означает исходные координаты геопозиции; `geocoded` — координаты Geoapify из текстовой отметки или старой миграции. Новые даты — ISO UTC. Пользовательские значения записываются как строки, без исполнения формул. Users и история сохраняются одним атомарным batchUpdate.

Поля `destination_*` независимы от текущей отметки. Отсутствующее назначение хранится пустыми ячейками; пустая координата не превращается в ноль. Изменение планов обновляет только их ячейки, не меняя время текущей отметки. Поиск сопоставляет код страны, регион/район и населённый пункт; для старых строк без кода страны используется нормализованное название страны. Отсутствующие старые районы не угадываются и появятся после новой отметки.

Settings хранит `pinned_message_id` первой части и, при необходимости, `pinned_message_ids` — JSON-массив ID дополнительных частей. Бот создаёт сообщение, сохраняет ID, закрепляет и затем редактирует его при старте и после успешных отметок. Удалённая часть восстанавливается отдельно; лишние части открепляются, их ID удаляются после успешного открепления. Старые закрепы не ищутся. Сбой закрепа не откатывает отметку; следующая попытка использует данные из Sheets.

Если права администратора выданы позже, событие `my_chat_member` сразу повторит настройку меню группы и обновление закрепа.

Отсутствующие листы создаются автоматически. Для текущей нормализованной схемы недостающие новые колонки дописываются справа одной операцией без перезаписи строк; перед изменениями проверяются заголовки всех рабочих листов. Повторный старт ничего не дописывает. **Старые несовместимые заголовки никогда не очищаются при запуске:** новая версия обслуживает HTTP в ожидании ручной миграции. Доступ к данным включается после миграции при следующем обращении, без перезапуска. Порядок колонок может отличаться, дополнительные поля сохраняются. Places не используется; посторонние листы не удаляются. Не редактируйте рабочие строки одновременно с ботом.

В Google Cloud включите Sheets API и предоставьте Spreadsheet service account с ролью Editor. Сам файл создаёт владелец. Бот должен быть администратором Telegram-группы с правом закреплять и отправлять сообщения. Администраторские права нужны также для надёжной [проверки членства](https://core.telegram.org/bots/api#getchatmember). Privacy Mode можно оставить включённым.

## Конфигурация

Скопируйте `.env.example` в `.env` или задайте переменные в Render Environment.

| Переменная | Назначение |
| --- | --- |
| `NODE_ENV` | `development` по умолчанию; `production` на Render |
| `LOG_LEVEL` | `debug`, `info`, `warn`, `error`, `silent`; по умолчанию `info` |
| `PORT` | HTTP-порт, по умолчанию 3000; на Render предоставляет платформа |
| `PUBLIC_BASE_URL` | HTTPS origin сервиса, без пути webhook |
| `TELEGRAM_BOT_TOKEN` | Токен BotFather |
| `TELEGRAM_GROUP_ID` | Отрицательный числовой ID целевой группы |
| `TELEGRAM_WEBHOOK_SECRET` | 1–256 символов `A-Z a-z 0-9 _ -` |
| `GOOGLE_SPREADSHEET_ID` | ID Spreadsheet |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | `client_email` service account |
| `GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY` | Полный PEM, поддерживаются переводы строк и буквальные `\n` |
| `GEOAPIFY_API_KEY` | Ключ Geoapify для прямого/обратного геокодирования и одноразовой миграции |

Вводите значения на Render без внешних кавычек. Старые Nominatim-переменные не используются. `.env`, ключи, логи и миграционные артефакты исключены из Git.

## Одноразовая миграция перед деплоем

**Для перехода с нормализованной схемы версии 3 скрипт не нужен:** новые колонки добавляются автоматически, прежние значения сохраняются, новые поля старых строк остаются пустыми. Шаги ручной миграции ниже относятся только к старой текстовой схеме. Скрипт поддерживает расширенную схему, сохраняет уже записанные назначения и не создаёт из планов события истории.

Миграция выполняется вручную отдельным скриптом. Она не подключена к CI/CD, сборке, старту или автоматическому деплою. После перехода скрипт можно удалить.

Сначала задайте Geoapify-ключ и выполните:

```sh
npm run migrate:locations -- --dry-run
```

Без аргументов тоже используется dry-run. Скрипт читает реальные заголовки и сохраняет **все исходные строки** в `migration-artifacts/<timestamp>/backup.json`, затем создаёт `preview.json` и `report.json`. Google Sheets в этом режиме не меняются. Отчёт содержит числа исходных, перенесённых и пропущенных строк, неизвестные/неоднозначные места и причины пропусков. Неизвестная схема требует явного сопоставления колонок.

Правила учитывают комментарии `Тверь(впишу) Россия`, стрелочные маршруты, регистр, сокращения вроде `спб` и регион Бали. Для маршрута берётся конечное место без создания дополнительных событий. Несколько уверенных разных кандидатов требуют ручной проверки. Геокодирование последовательное с паузами, без повторов; при 429 или сбое провайдера применение блокируется.

При необходимости создайте локальный JSON с переопределениями исходных строк:

```json
{
  "неоднозначное место": "Уточнённое место, Страна",
  "исключить эту запись": null
}
```

```sh
npm run migrate:locations -- --dry-run --overrides=overrides.json
```

Скрипт сохраняет исходные даты, user ID, существующие события и дополнительные поля; исходный текст остаётся также в `legacy_location`. Недостающие даты и события не выдумываются. Пропущенные записи остаются в backup и отчёте. Повторный запуск не дописывает историю. Backup содержит значения и формулы, но не оформление таблицы; для полного восстановления можно дополнительно скопировать Spreadsheet в Google Drive.

Если у существующего события истории нет даты, оно переносится с пустой датой и предупреждением в отчёте. Для PowerShell используйте `npm.cmd --% run migrate:locations -- --dry-run --overrides=overrides.json`, если оболочка не передаёт аргументы через `npm.ps1`.

После проверки preview/отчёта и **отдельного разрешения владельца** убедитесь, что Render уже переключился на новую версию и завершил старый процесс, затем запустите:

```sh
npm run migrate:locations -- --apply --overrides=overrides.json
```

Если overrides не нужны, уберите этот аргумент. Apply создаёт свежую резервную копию, повторно сверяет источник и одной атомарной операцией обновляет рабочие листы. Settings и посторонние листы сохраняются. Отчёты содержат персональные данные: храните их надёжно, overrides с такими данными также не коммитьте.

## Безопасный порядок деплоя на Render

При обновлении нормализованной версии 3 достаточно развернуть новый код одним инстансом с прежними env и командами Build/Start. Схема расширится при старте. Проверьте геолокацию и текстовую отметку, новую строку истории, изменение/очистку планов без новой истории, `/find` и одинаковые части `/list` и закрепа. Новые переменные окружения и изменения Render/GitHub Actions не требуются.

Для перехода со старой несовместимой текстовой схемы:

1. Подготовьте `GEOAPIFY_API_KEY` локально и в Render, дайте боту права администратора и закрепления.
2. Выполните dry-run, проверьте пропуски и overrides. Сохраните резервную копию вне временного диска Render.
3. Сначала разверните новую версию. На старой схеме она работает в ожидании ручной миграции и возвращает временную ошибку при обращении к данным. Старые записи сохраняются.
4. Разверните новую версию одним инстансом. Build Command: `npm ci --include=dev && npm run build`.
5. Start Command: `node dist/scripts/register-webhook.js && npm run start`. Environment: `NODE_VERSION=26`, `NODE_ENV=production`, остальные значения из таблицы. В `PUBLIC_BASE_URL` — реальный HTTPS origin Render.
6. Health Check Path: `/health`. Дождитесь `webhook_setup_completed` и `app_ready`. Проверьте `200 {"status":"ok"}`, `X-App-Version: 1.0.1` и `X-App-Revision` с SHA нового коммита. Дождитесь завершения старого процесса Render, затем выполните разрешённый apply. Старую версию 2 после миграции запускать нельзя: она умеет очищать несовместимую схему.
7. Проверьте личные `/start`, геопозицию, текстовую отметку, запись истории, планы, `/find`, `/list` и закреп в группе. Затем можно восстановить обычный автодеплой и удалить одноразовый скрипт с его тестами и npm-командой.

Setup регистрирует защищённый webhook с `max_connections=1`, `allowed_updates=["message","callback_query","my_chat_member"]`, без удаления ожидающих updates. Он обновляет описание и меню для лички/группы. Ошибка webhook останавливает запуск; ошибка меню целевой группы логируется как предупреждение. При добавлении бота позже меню этой группы устанавливается снова. Polling не используется.

## Локальный запуск и проверки

Нужен Node.js 26.x:

```sh
npm ci
npm run test
npm run lint
npm run typecheck
npm run build
npm run dev
```

Для локального webhook нужен HTTPS-туннель к порту 3000, его origin в `PUBLIC_BASE_URL` и `npm run webhook:set`. Это переключает Telegram с Render на локальный адрес. Используйте одну установку бота одновременно. `npm run start` запускает собранную версию.

CI запускает test, lint, typecheck и build на Node.js 26 без секретов и настоящих API. Миграционные тесты используют моки и не запускают миграцию production. Override `minimatch` фиксирует уязвимость зависимости ESLint; при обновлении инструментов проверяйте `npm audit` и lint.

## Диагностика

Данные хранятся в Sheets, а не на диске Render.

JSON-логи идут в stdout/Render Logs. `info` — запуск и сохранение, `warn` — недоступное меню или чужой чат, `error` — ошибки Sheets, геокодера, Telegram и закрепа. Ошибки содержат безопасный код/HTTP-статус и длительность; SDK payload, stack, токены, координаты и персональные данные не выводятся. `/health` не засоряет логи. `location_saved` означает подтверждённую запись, даже если ответ Telegram затем не доставлен.

При `sheets_migration_required` новая версия ожидает ручную миграцию; следующее обращение после неё подхватит новую схему. При сбое закрепа проверьте администраторские права; данные уже сохранены, повторная геопозиция добавит ещё одно событие истории. При неопределённом результате записи сначала проверьте таблицу: автоматического повтора нет. Повторная доставка webhook может добавить лишнюю историческую строку. Нет удаления/TTL, карт, просмотра истории в Telegram и поддержки нескольких групп.
